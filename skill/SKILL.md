# SPD で構造化ロジックを書く

この Skill は、SPD を**一度で正しく書く**ための文法と規則である。ここに書いた規則だけで
書けるようにしてある。文法の詳細と根拠は [reference/spd-grammar.md](reference/spd-grammar.md)。
padtools_ts の文法ファイル（`spd.langium`）は実装と食い違う点があるので、それを根拠に書かない。

## 規則 0：インデントは実タブだけ

**行頭のタブ 1 個 = 1 段。スペースは一切使わない。**

スペースで字下げすると、padtools_ts は終了コード 0 のまま入れ子を全部捨て、
`:if` などを文字列の箱として描く。誰も気づかない。

- SPD は**ファイルに書く**。チャットのコードブロックではタブがスペースに化けることがある
- スペースで書いてしまったら `padkit fix-indent -w FILE.spd` でタブに直す

## 文法

1 行 = 1 つの箱。行頭（タブの後）が `:` なら命令、それ以外は処理の箱。
1 段深い行は、直前の 1 段浅い行の子になる。最初の行は字下げしない。一度に 2 段深くしない。

| 書き方 | 意味 | 子ブロック |
|---|---|---|
| `文` | 処理 | 可（その処理の詳細） |
| `:if 条件` | 分岐の真側 | 真の処理 |
| `:else` | 直前の `:if` の偽側。`:if` と**同じ深さ**。引数を書かない | 偽の処理 |
| `:switch 式` | 多分岐の頭 | **不可** |
| `:case 値` | `:switch` の直後に**同じ深さ**で並べる分岐肢。値は重複不可 | その肢の処理 |
| `:while 条件` | 前判定ループ | 本体 |
| `:dowhile 条件` | 後判定ループ | 本体 |
| `:call 名前` | 別の図の呼び出し（二重線） | 可（要約） |
| `:terminal 文言` | 終端（角丸） | **不可** |
| `:comment 文言` | 注記（枠なし） | **不可** |

- `:else` 以外の命令は引数が**必須**
- `@` は箱の中の改行。`\@` は文字の `@`
- `#` で始まる行は無視される。**行の途中の `#` はコメントにならず、文字として描かれる**

```spd
リリースを行う
	:comment 準備
	リリース対象のコミットを定める
	:while 未解決の不具合が残っているか
		不具合を一件選ぶ
		:if 今回のリリースで直すべきか
			修正して回帰テストを追加する
		:else
			次版のマイルストーンへ移す
	:switch 公開先はどこか
	:case PyPI
		wheel と sdist をアップロードする
	:case 社内配布
		社内レジストリへ登録する
	:terminal 完了
```

## 書いてはいけない形

padtools_ts が**エラーを出さずに**図を壊す。どれも実測で確認したもの。

| 書いてはいけない | 起きること | 代わりに |
|---|---|---|
| スペース・混在の字下げ | 入れ子が消える | タブだけ |
| 命令の綴り違い（`:ifx`, `:whilex`） | 別の命令として読まれ、子が消える | 表の命令名だけを使う |
| 処理の箱の **2 文字目**が `#`（`C# で書く`） | 次の行と 1 つの箱に融合する | 「C 言語系の # …」のように言い換える |
| `:else` の行にコメント（`:else  # 失敗時`） | else 側が丸ごと消える | コメントは別の行に |
| 最後の行が、字下げされた **1 文字だけ**の箱 | その箱が消える | 2 文字以上にする |

## 書き方の作法

- 処理は**動詞で終える**（「〜する」「〜を定める」）。体言止めにしない
- 条件は**疑問形**（「〜か」）。真になる側が読み取れる形にする
- 1 行は全角 20 字以内。長ければ短く言い切るか `@` で折る
- `:comment` は構造に影響しない。段落見出しに使ってよい
- `:terminal` は正常終了にも破綻にも使える。両方あるなら文言で区別する（「完了」「撤退：資金が尽きる」）
- 深さが 5 を超えそうなら、その部分を別の図に切り出して `:call` で呼ぶ

## 書いた後：必ず検査する

```
padkit lint FILE.spd                     # padkit がある場合（推奨）
python3 scripts/spd_lint.py FILE.spd     # ない場合（この Skill の同梱）
```

**error が 0 になるまで直してから**渡す。`padkit lint` は padtools_ts が実際に組む構造と
書いた構造を突き合わせるので、上の表に無い壊れ方も E900 として出る。
診断コードは [reference/lint-codes.md](reference/lint-codes.md)。
入れ子が意図どおりか確かめたいときは `padkit ast FILE.spd` で構造を読み戻す。

描画は `padkit svg FILE.spd -o FILE.svg` / `padkit pdf FILE.spd -o FILE.pdf`。
同じ深さの箱を列に揃えたいときは `--align-depth` を付ける（PAD 規格外の拡張）。

## 構造の講評（計画・設計を書いたとき）

SPD にした対象が、ユーザーの検討中の計画や設計であるときは、lint の warning / info を
材料に構造の講評を添える。PAD にすると散文では見えない欠陥が形になる：本流の途中の
`:terminal`（その設計が成り立たない点）、`:while` の欠如（学習ループが無い）、
`:else` の無い `:if`（失敗時の経路が未定義）。観点と出力形式は
[reference/review-checklist.md](reference/review-checklist.md)。

アルゴリズムや既存手順を書き写しただけのとき、またはユーザーが SPD そのものだけを
求めたときは、講評を省いてよい。
