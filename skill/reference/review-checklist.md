# 構造レビューの観点

PAD にした計画・手順を、**図の見た目ではなく設計として**講評するための観点表。
lint の warning / info はこの表の機械的に数えられる部分に対応している。

| 観点 | 徴候 | 示唆 | lint |
|---|---|---|---|
| `:terminal` の数と位置 | 本流の途中に多い | 設計の破綻点。引き返す先がない | I303 |
| `:while` / `:dowhile` の有無 | ゼロ、または極端に少ない | 反復・学習ループが設計に入っていない | I301 |
| `:else` の欠落 | `:if` 単独が多い | 片道の分岐。失敗時の経路が未定義 | I302 |
| ネスト深さ | 5 を超える | 粒度が揃っていない。`:call` で別図に切り出す | W201 |
| `:call` の有無 | ゼロで図が巨大（60 箱超） | 分割すべき | W204 |
| 兄弟数 | 一つの親に 15 超 | 中間の括りが欠けている | W203 |
| 1 行の幅 | 全角 20 字超 | 言い切れていない。図が横に伸びる | W202 |

## 読み方

### `:terminal`

角丸の終端は、直線的な処理ボックス列の中で視覚的に浮く。本流の途中にあれば、
それは「条件を満たさないと次へ進めない」ではなく「**その設計自体が成り立たない**」
箇所であることが多い。一つずつ次を判定する。

- 正常終了か、破綻か（文言で区別されているか）
- 破綻なら、手前に回避・撤退・やり直しの経路（`:else` や `:while`）を置けないか
- 置けないなら、それは計画の前提条件であり、図の外で先に確かめるべきこと

### 反復

`:while` が無い計画は、一度通しで実行したら終わる一本道である。
試行・測定・修正の循環が要る箇所（顧客検証、品質改善、採用など）に反復が無ければ、
その計画は**学習しない**。どこにループを入れるべきかを具体的に指摘する。

### 片道分岐

`:else` の無い `:if` は、条件が偽のときに何もしないと宣言している。
それで正しい場合（任意の追加処理）と、失敗時の経路を書き忘れている場合を区別する。

### 粒度

深さ・兄弟数・幅の警告は、どれも「一つの図に違う抽象度が混ざっている」徴候である。
深い部分を `:call` で別図に切り出すか、兄弟を中間の処理でまとめる。

## 講評の出力形式

```
## 構造の講評
- 統計: 処理 n / 分岐 n（else あり n）/ 反復 n / 終端 n / 呼出 n、最大深さ n
- 終端: …
- 反復: …
- 片道分岐: …
- 粒度: …
- 最も重い欠陥: …（一つ選び、設計上の帰結を書く）
```

統計は `padkit lint --format json`（または `spd_lint.py --json`）の `stats` から取る。
該当なしの観点は「該当なし」と書き、省略しない。
